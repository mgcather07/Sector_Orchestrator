# Android Parity Assessment

**Date:** 2026-08-23 · **Method:** 9-agent parallel workflow audit — one read-only auditor per feature group, each cross-checking **iOS as source of truth** against **current** Android source (`app/src/main/java/io/sector/co/`), deliberately not trusting the prior 2026-08-22 snapshot. **No build or on-device verification was run** — nothing here is `verified_implemented`; read-only evidence maps to `implemented_unverified` / `partial` / `missing` / `verification_pending`.

## Executive summary

Android sits at **near-full functional parity** with iOS, and materially closer than the stale 2026-08-22 audit implies. Across Groups C, E, G, and H the current Android source has quietly closed most of what that doc flagged as "partial/missing" — store-owner role-request approval (`ListYourStoreForm`), the Redzones approvals tab, live role listeners, the force-prod database-environment guard, cloud restore-on-login, and the whole Feed/Social/BAA-Records surface are all present now. The dominant risk in those groups is **verification, not missing code**: everything is `implemented_unverified` pending a device/build pass. The stale doc should be corrected on at least five points it now gets wrong (store approval, admin-tools, Apple Sign-In labeling, trip cloud I/O absence, cloud-sync trip-exclusion).

The real gaps cluster into a few **themes**. First, **OS-integration and platform features that don't port cleanly**: background geofencing is dormant (no `ACCESS_BACKGROUND_LOCATION`, so zone alerts are foreground-only), Apple Sign-In is entirely absent despite the spec requiring it, and Google Sign-In leans on the deprecated GMS API. Second, a **pervasive Firebase Analytics instrumentation gap** — redzone, tournament, guide, and store events specified by iOS are logged nowhere on Android, breaking cross-platform funnel parity in nearly every group. Third, **subscription/gate and data-shape divergences** (boat-tracks free cap 3 vs 2; `PublicUserMirror` writing a different projection with extra social keys and full-blank writes). Fourth, a set of **UX/polish regressions** — static dashboard gauge vs the animated semicircle, guide reviews rendered fully inline, missing loading/error/signed-out states.

Two items rise above polish. The **boat-tracks privacy leak** (no `ownerUid`, no per-user filtering, recording continues through sign-out) is a genuine CRITICAL — a second account on a shared device sees the first user's full GPS history, the exact leak iOS explicitly guards. And the **tournament browse filter is silently unreachable** on Android (the toolbar button was removed while the filter sheet stayed fully built), so State filtering and sort are dead functionality, not a missing build.

Group F is reassuring on the biggest structural question: conditions scores do **not** diverge — both platforms score off the one shared Cloud Run SectorEngine — so parity there is structural, and the nightly Lake Conditions Alerts loop is absent on both platforms equally.

## Biggest gaps (ranked)

1. Boat tracks have no ownerUid and no per-user filtering — a second account on a shared device sees the first user's full GPS history, and recording never stops on sign-out (CRITICAL privacy leak iOS explicitly guards)
2. Background geofencing is dormant: ACCESS_BACKGROUND_LOCATION is never declared or requested, so zone-entry alerts fire foreground-only and the 'works when the app is closed' promise is unmet
3. Apple Sign-In is entirely absent on Android despite auth.md requiring it (stale doc wrongly labels it excluded-by-design)
4. Tournament browse State filter and Latest/Name sort are unreachable — the toolbar filter button was removed so the fully-built filter sheet never opens, silently dropping functionality vs iOS
5. Pervasive Firebase Analytics gap: redzone (viewed/entry/exit), tournament (rsvp/comment), guide (contact/review), and store (viewed/website/contact/review) events specified by iOS are logged nowhere on Android
6. Google Sign-In uses the deprecated GMS GoogleSignIn API instead of Credential Manager/Google Identity — functional but on borrowed time and a historical source of Play Services errors
7. PublicUserMirror diverges: Android writes the full projection including blanks and adds instagram/tiktok/twitter keys beyond iOS's documented set — mirror shape and write semantics differ across platforms
8. Boat-tracks free cap is 3 on Android vs 2 on iOS — a subscription-gate divergence that should match
9. Guide profile renders all reviews inline, missing the iOS 3-review preview + 'See all N reviews' sheet and prefer-written-reviews ordering
10. Dashboard hero gauge is a static full-circle ring, missing iOS's animated semicircle gauge (0→score count-up, drain/refill living-loading states)
11. Guide profile hero overlays name/rating/location on the image instead of the spec's body title header with socials row
12. Custom markers lack a 'Use current location' button and use per-type tinting instead of iOS's 4-category color model, causing Spot pin/tile/pill color drift
13. Android engine DTO drops iOS-only render fields (baseline, dormantFactors, MRMS clarityRain), giving a thinner score breakdown and clarity detail
14. Regulations in-app PDF viewer lacks in-document text search and the 'X of N' match counter iOS PDFKit provides
15. Address entry uses device android.location.Geocoder autocomplete instead of Google Places / Mapbox Search, yielding weaker, POI-poor suggestions vs iOS MKLocalSearchCompleter
16. Signed-out comment composer stays visible and only Toasts on send instead of iOS's 'Sign in to join the conversation' prompt; guide/booking sign-in guards use Toasts instead of the spec's alert dialogs
17. My Tournaments lacks the distinct Loading, 'Not logged in', and red Error states iOS renders
18. Android master-tools menu omits the Analytics / Active Users / Firebase Usage admin panels present in the iOS dashboard
19. Deal manage-list sort only pushes expired last rather than active/scheduled-first, and 'one featured at a time' isn't an atomic multi-path write
20. baa-record-submit dropped the iOS 'Still needed' outstanding-items list, keeping only the completeness ring
21. Tournament venue trophy pins + clustering exist (redzones/TournamentMapPins.kt) but wiring/clustering parity is unverified
22. Subscriptions and App Check are structurally complete but need live-environment confirmation (Play Console product + on-device purchase/restore; App Check debug-token registration) before production trust
